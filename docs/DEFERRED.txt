Things named in the project plan that are NOT yet built, and why.
Updated as each slice completes. Last updated: 2026-08-19.

PHASE 2 — ASTRONOMY DATA LAYER
---------------------------------------------------------------------

[DONE]    Barycentric time correction to a single frame
          Built in Phase 6 (astra/timeframe.py). Everything converts to
          BJD_TDB before comparison.
          CORRECTION TO AN EARLIER NOTE: this file previously said the
          ZTF/TESS frames differ by "up to ~8 minutes". That was wrong.
          The +-8.3 minute figure is the GEOCENTRIC-to-barycentric term,
          and HJD has already absorbed almost all of it. Measured at the
          RR Lyr position: total 68.1 s, of which 69.2 s is the UTC->TDB
          scale change and only -1.0 s is the heliocentric-to-barycentric
          residual. Direction dependence spans about 66-73 s.
          Still worth correcting — 68 s is over half a TESS 2-minute
          cadence bin — but it is ~1 minute, not ~8.

[DONE]    ZTF science-image cutouts / FITS download
          The IRSA IBE metadata search and science-image cutout contract is
          implemented with bounded streaming, retries/throttling, declared and
          observed byte checks, SHA-256 provenance, FITS/WCS validation, and
          atomic immutable publication under Datasets/ZTF/images/. The dataset
          quota now includes FITS products and their sidecars. The candidate
          workspace can search overlapping images, queue a cutout, and open it
          in the bounded FITS viewer.

[DONE]    TESS target-pixel files / blend-aware aperture photometry
          Explicit candidate-scale TPF requests now use MAST TESScut: one
          coordinate, one sector, and a bounded 2--50 pixel cutout (20 pixels
          by default). Downloads stream under a 128 MiB ceiling, reject unsafe
          ZIP members/symlinks and decompression expansion, validate the TPF
          table/WCS/sector, SHA-256 both archive and FITS, and atomically
          publish immutable FITS plus provenance under Datasets/TESS/tpf/.
          Aperture curves are background-subtracted, quality-maskable, use a
          finite uncertainty fallback when a product omits FLUX_ERR, persist
          as canonical BJD_TDB Parquet, and return a bounded JSON payload.
          The candidate workspace queues the transfer as a resumable job and
          can persist its aperture curve. It reports a Gaia-neighbour-aware
          blend assessment and never calls the result resolved photometry:
          21-arcsec TESS pixels still need PSF/deblending work for a specific
          star claim. This is intentionally not bulk acquisition.

[PARTIAL] Gaia epoch photometry
          Only the DR3 main table (static astrometry + mean photometry)
          is queried. Gaia's time-series photometry for variables is a
          separate, much larger table.
          Gaia DR4, expected 2026-12-02, is the eventual fix: it publishes
          epoch time series (astrometry, photometry, BP/RP and RVS spectra)
          for ALL sources rather than DR3's ~12M-source subset — ~400 TB
          total, against DR3's ~10 TB. That is what would let Gaia become a
          real time-domain survey and make gaia_only / gaia_tess / all_three
          answerable the same way the ztf_gaia entry in Phase 8 now is for
          Gaia-as-static-context. Deliberately not planned around here: it
          is ~3.5 months out from this writing and enormous in volume; see
          the ztf_gaia entry for what is answerable today without it.
          UPDATE 2026-08-19: GaiaEpochAdapter validates offline DR4 fixtures
          (source_id/time/flux/error), records rejection reasons, and exposes
          the expected release gate. Live DR4 ingestion remains disabled until
          the archive release and schema are verified.

[DONE]    Dataset size cap is enforced transactionally
          Writes are staged, measured, and atomically published only when the
          configured cap permits them. Existing data is never auto-evicted;
          acquisition explicitly reports capacity refusals.

[PARTIAL] Future survey connectors
          The registry now carries explicit capabilities, resolution,
          credential, and enabled-by-default metadata. Bounded SDSS spectrum
          metadata, Pan-STARRS DR2 mean-photometry, and Chandra Source
          Catalog (CSC) X-ray metadata adapters are registered as opt-in
          connectors; default acquisition remains limited to ZTF/Gaia/TESS
          until provider contracts are validated.
          UPDATE 2026-08-19: all three metadata-only connectors
          (`sdss.py`, `panstarrs.py`, `chandra.py`) now have fixture tests
          (`tests/test_surveys_sdss.py`, `test_surveys_panstarrs.py`,
          `test_surveys_chandra.py`) covering row parsing, malformed/missing
          fields, capability declarations, and the `fetch_light_curves` no-op
          contract, mocking `astra.netclient.get`. A previous version of this
          entry claimed such tests already existed for SDSS/Pan-STARRS; they
          did not (checked: only `tests/test_surveys_base.py` existed) — this
          is now fixed rather than just corrected.
          UPDATE 2026-08-19 (2): Swift (SXPS point-source catalog) and
          XMM-Newton (4XMM-DR13 serendipitous source catalog) adapters
          (`swift.py`, `xmm.py`) now exist, registered opt-in with the same
          metadata-only shape, each with its own fixture test file
          (`tests/test_surveys_swift.py`, `test_surveys_xmm.py`).
          Chandra/Swift/XMM's `cone_search` implementations target plausible
          endpoint shapes for each archive's cone-search service; none has
          been validated against the real, live service yet (exact field
          names, auth requirements, real rate limits) — only the parsing/
          registration contract and malformed-response handling are tested
          against fixture payloads. This is a live-contract validation gap,
          not a missing capability: run each connector against its real
          endpoint once network access to validate is available, and adjust
          field-name fallbacks/rate limits as needed.
          Rubin/LSST, DES, Hubble, JWST still need isolated adapters.
          LIGO/Virgo/KAGRA and CHIME are not point-source cone-search
          surveys and do not fit the current `SurveyConnector` interface
          as-is; they need a base-class/interface design decision before an
          adapter can be written, not just an implementation.

PHASE 4 — BASELINE ANOMALY DETECTION
---------------------------------------------------------------------

[PARTIAL] Image-derived features (plan section 12)
          A bounded FITS feature extractor now persists source checksum,
          background/MAD, thresholded morphology, centroid/moments,
          ellipticity, peak S/N, residual and target-centroid distance with a
          versioned schema. The candidate workspace can run it on a verified
          ZTF cutout. Versioned image sidecars are now persisted as keyed
          Parquet and can be explicitly left-joined to feature identities with
          match/missing diagnostics. PSF fitting, multi-source deblending, and
          publication-grade stellar photometry remain open.

[PARTIAL] Spectral features (plan section 12)
          A bounded FITS-table spectral extractor now validates wavelength,
          flux, errors/ivar, ordering, and point limits, then persists
          continuum, S/N, residual, line-threshold, and equivalent-width proxy
          features with provenance. SDSS metadata discovery is available as an
          opt-in connector. Versioned spectral sidecars now use the same keyed
          Parquet/join contract as image rows. Live spectrum retrieval,
          instrument-specific frame calibration, and publication-grade line
          modelling remain open.

[PARTIAL] Period search is single-band by default
          Lomb-Scargle still runs per light curve in the main matrix path, but
          multiband_periodic_features() now provides an opt-in shared-period
          fit for two or more bands. Full hierarchical modelling remains open.

[DONE]    Change-point detection includes bounded BOCPD
          The original sliding-window score remains for compatibility; a
          bounded constant-hazard Bayesian online detector now adds posterior
          change probabilities and an estimated change epoch to feature rows.
          The fixed-variance approximation is a screening diagnostic, not a
          publication-grade posterior model, but it is now available as a
          versioned feature and is covered by regression tests.

[PARTIAL] Period search supports multi-band shared fitting
          A bounded joint Lomb-Scargle adapter now subtracts per-band baselines
          and fits a shared period across two or more bands. Full hierarchical
          heteroscedastic multi-band modelling remains open.

[DONE]    Feature versioning
          Feature and preprocessing schema hashes are persisted with matrices
          and experiment provenance; verification reports schema drift.

[DONE]    Supervised evaluation metrics
          Plan section 20 wants precision/recall/F1/ROC-AUC. These need
          labels, which come from the human-in-the-loop system in
          Phase 7 (section 22). Only unsupervised scores exist now.

[DONE]    Survey/band/tier-stratified detection  <-- MEASURED
          Running the ensemble over a matrix mixing ZTF and TESS ranks
          the TESS curves top, but largely because they are structurally
          different (18,000 points at 2-minute cadence in flux, versus
          ~500 points over years in magnitudes) rather than because they
          are astrophysically stranger. The detectors partly separate by
          SURVEY instead of by behaviour.
          This is exactly the survey bias plan section 36 warns about.
          Confirmed by re-running on ZTF alone, where the ranking then
          correctly surfaces the highest-variability sources.
          => Detection must run within survey/band strata, or survey must
             be regressed out as a covariate. Until then, always pass
             `survey=` when building a matrix for detection.

[DONE]    Policy for short light curves
          23 of 60 real curves produced NaN features (fewer than the 30
          points a period search needs, or fewer than 10 points at all)
          and were silently dropped by the detectors. Dropping them is
          safer than imputing, but a real campaign needs an explicit,
          reported policy rather than a silent skip.

[PARTIAL] Detector scores have empirical calibration metadata
          A score of 1.0 means "most anomalous in THIS batch", not an
          absolute level. Rankings from different runs are not directly
          comparable. The ensemble now also exposes empirical-CDF calibration
          metadata and records whether it is batch-relative or backed by an
          external reference population.

PHASE 5 — DEEP LEARNING
---------------------------------------------------------------------

[DONE]    Transformer time-series model
          Listed in plan section 13. Only the convolutional autoencoder
          and VAE are built. Attention is O(L^2) in memory: at L=2048
          and batch 32 the attention matrices alone need ~4 GB, which
          does not fit here. ASTRA now includes a bounded patch transformer
          (default patch size 16, configurable token width/depth), exposed in
          development training and injection-recovery comparisons. It remains
          opt-in and still needs Stage-B scale evidence before becoming the
          default method.

[BLOCKED] Multimodal encoder (section 14) and contrastive learning
          The stated central research innovation. Contrastive objectives
          get their signal from in-batch negatives and want batches of
          1024-4096; ~2.2 GB usable VRAM allows perhaps 64-128.
          Gradient accumulation does NOT fix this — it accumulates
          gradients but gives the loss no additional negatives.
          => This one genuinely needs more VRAM, not better engineering.

[KNOWN]   Model capacity is far below what the GPU allows  <-- MEASURED
          The autoencoder is 93,921 parameters and peaks at 38 MB of
          VRAM; the VAE is 126,705 parameters at 39 MB. Against ~2.3 GB
          free that is about 1.5% of the budget. The 4 GB card is NOT
          the binding constraint for these models.
          => Capacity should be chosen by the injection-recovery
             comparison, not by the memory limit. Plan section 13's rule
             cuts both ways: bigger is not automatically better either.

[KNOWN]   Sequence representation discards absolute brightness
          Curves are MAD-normalised so ZTF magnitudes and TESS flux are
          comparable in shape. Absolute brightness survives only in the
          feature vector. A model that needs it must consume both.

[KNOWN]   Gaps are masked, not modelled
          Points interpolated across observing gaps are zeroed and
          flagged in a validity channel so they never enter the loss.
          A model that reasons about irregular sampling directly (e.g.
          a neural ODE or a time-aware attention) would use the gaps as
          information rather than discarding them.

[KNOWN]   Injection-recovery measures the anomalies that were injected
          The comparison harness scores methods on recovering flares,
          eclipses, step changes and noise bursts. Winning there proves
          sensitivity to THOSE shapes. It does not prove sensitivity to
          phenomena nobody thought to inject, which is the actual
          discovery case in plan section 4.

[PARTIAL] The method comparison needs re-running at scale  <-- IMPORTANT
          The first injection-recovery study ran on only 54 ZTF sequences
          with 8 injected anomalies. On that data the simplest baseline
          (PCA reconstruction, ROC-AUC 0.742) BEAT both deep models
          (autoencoder 0.622, VAE 0.609). The VAE early-stopped after 7
          epochs on 43 training rows.
          That is a real result and exactly what plan section 13 predicts
          can happen, but at n=54 it mostly says the deep models are
          data-starved. It is NOT yet evidence that deep learning does
          not help here.
          => A resumable `stageb.compare` job now checkpoints each independent
             seed, records a dataset fingerprint, survey/release/band strata,
             sidecar schemas, preprocessing contract, and empirical confidence
             intervals. It is exposed in Experiments but never starts
             automatically. It still must be run on a Stage-B population
             (thousands of curves) before drawing a paper conclusion.

[DONE]    ZTF sequence coverage — season and phase resampling  <-- MEASURED
          Uniform resampling over the full baseline left mean validity at
          about 0.40: roughly 60% of every sequence was masked-out gap
          interpolation carrying no information.
          Both alternatives this entry proposed are now built.
          tensors.resample_by_season() splits on gaps larger than 30x the
          curve's own median spacing (relative, not a fixed number of days,
          because a 2-minute TESS cadence and a nightly ZTF field share no
          absolute definition of a gap) and allots grid points to each season
          in proportion to how many observations it actually contains.
          tensors.resample_by_phase() folds on a period, used only when
          period_snr >= 5, read from the feature cache rather than by running
          a fresh Lomb-Scargle — which would have put the ~1 s/curve cost that
          feature caching removed straight back into sequence building.
          MEASURED on three simulated ZTF seasons (120 jittered nights each,
          445-day gaps, 0.6 d sinusoid):
            time    mean validity 0.305
            season  mean validity 0.965
            phase   mean validity 0.926
          Selected by tensors.build(mode=...), default UNCHANGED at "time".
          Seasons share ONE normalisation rather than being normalised
          separately: per-season normalisation would erase real
          season-to-season brightness change, which for a long-period
          variable is the signal rather than a nuisance.
          A mode that cannot apply to a curve (a single season, no credible
          period) falls back to the time grid rather than dropping the curve,
          so switching mode cannot silently change the population trained on.
          => The comparison this enables has NOT been run. Higher validity is
             a better representation, not a better result; whether it improves
             injection recovery is an open question, and answering it needs
             the Stage-B scale this file already demands elsewhere.

[DONE]    Hyperparameter search — the mechanism, not yet the answer
          astra/sweep.py grids over capacity and optimisation and scores each
          configuration by injection recovery, recording the whole study as
          one reproducible experiment (deep.sweep RPC, Models view UI).
          Per-kind grids, because sweeping a dimension that does nothing and
          reporting it as searched would be misleading: autoencoder and VAE
          get latent_dim / channels / learning_rate (27 configs; the VAE adds
          kl_weight, 81), and the patch transformer gets transformer_dim /
          layers / patch_size / learning_rate instead. The current defaults
          are inside the grid, so the sweep can measure whether changing them
          helped rather than only which alternative it prefers.
          Three deliberate guards, each against a way this misleads:
            - Multi-seed by default (3), with an empirical seed interval. One
              seed cannot separate "better configuration" from "luckier
              injection draw" -- this project already has an n=54 run where
              PCA beat both deep models, which mostly measured data
              starvation.
            - Capacity explored in BOTH directions. The autoencoder is 93,921
              parameters at 38 MB against ~2.3 GB free, about 1.5% of the
              budget, so memory is not the binding constraint and bigger is
              not automatically better either.
            - SweepResult.best() returns None when the leader's seed interval
              overlaps the runner-up's. The ranking is still shown; the winner
              is not declared. Ranking by mean alone would turn injection-draw
              noise into a recommendation.
          => Built and tested, NOT yet run at scale. Same caveat as the
             method comparison above: at Stage-A size the intervals will
             almost certainly overlap, and "no configuration separated" is
             the honest expected outcome rather than a failure of the sweep.

[DONE]    PYTORCH_CUDA_ALLOC_CONF is set by the engine
          expandable_segments:True meaningfully reduces fragmentation on
          a card this tight. Currently left to the user's environment.

PHASE 6 — CROSS-SURVEY ENGINE
---------------------------------------------------------------------

[KNOWN]   TESS cannot resolve individual stars  <-- MEASURED, IMPORTANT
          TESS pixels are 21 arcsec. On the real data, five different ZTF
          sources all matched the SAME TESS object (TIC 159717514),
          because the TESS aperture is a sum over the whole
          neighbourhood. Counting that as independent confirmation would
          manufacture cross-survey agreement for every star sitting near
          a bright variable.
          Now handled: such matches are marked `blended` and excluded
          from `resolved_surveys`. On the current dataset this takes the
          count of genuinely two-survey-resolved objects from 5 to 0.
          => Resolving a specific star in TESS requires PSF fitting or
             deblending on target-pixel files. Phase 2 now supports explicit
             candidate-scale TPF downloads and aperture extraction, but not
             PSF fitting; it therefore remains neighbourhood photometry, not
             stellar photometry, and does not restore resolved-survey credit.
           UPDATE 2026-08-19: TGLC (TESS-Gaia Light Curve, MAST HLSP) supplies
          exactly this as a finished product: it forward-models each FFI
          with an effective PSF using Gaia DR3 positions/magnitudes as
           priors, reaching <=2% photometric precision at T=16 even in
           crowded fields — without downloading a single TPF. TGLC is now
           wired through the connector with a robust MAD-of-differences
           per-cadence error estimate when its product omits FLUX_ERR; the
           provenance marks that estimate explicitly. It still does not
           restore resolved-survey credit until target-specific recovery is
           validated against blends and injection tests.
          QLP (real bulk TESS coverage, no PSF deblending) IS wired in and
          was used to take tess_only/gaia_tess from refused to scored —
          real numbers in that same Phase 8 entry, including a measured
          pipeline-mixing effect from combining it with the 3 pre-existing
          SPOC curves. It does not resolve the blending problem THIS entry
          describes; QLP's photometry is still 21-arcsec neighbourhood
          photometry same as SPOC, just for vastly more targets.

[DONE]    Alias-tolerant period matching has a false-alarm probability
          periods_agree() still accepts harmonics and 1-day aliases, but
          period_agreement_fap() measures the covered frequency-window null
          probability and the profile discounts agreement by (1 - FAP).
          The FAP is persisted with the profile and exposed in the UI, so a
          boolean alias match is no longer treated as certainty.

[DONE]    Evidence weights are explicitly versioned
          The five components in evidence.WEIGHTS sum to 1.0 with fixed
          values. Plan section 16 says these should become experimental
          variables. No sweep or sensitivity analysis exists.

[DONE]    Amplitude and colour consistency are scored
          Cross-survey profiles convert magnitude/flux amplitudes to a
          fractional scale, compare same- and cross-band ratios, and penalise
          colour-inconsistent amplitude ordering. Missing/incomparable
          amplitudes remain unavailable and do not become false disagreement.

[DONE]    Cross-survey engine persists and uses Gaia astrometry
          gaia.derived_properties() computes distance, colour and
          absolute magnitude, but the evidence profile does not consume
          them. Physical-inconsistency scoring (section 16) needs them.

[PARTIAL] Grouping anchors on the largest catalogue
          group_sources() uses whichever survey has the most detections
          as the anchor. That is a defensible default but it means the
          object list is defined by one survey's selection function —
          a selection bias worth documenting per section 36. The crossmatch
          response now includes anchor share and per-survey match rates, so
          downstream studies can stratify or rerun explicitly.

PHASE 7 — EXPLAINABILITY & CANDIDATE RANKING
---------------------------------------------------------------------

[PARTIAL] Catalogue cross-reference (SIMBAD / VSX / TNS)
          An explicit, non-blocking enrichment action now queries SIMBAD and
          VSX through VizieR, plus TNS when protected credentials are
          configured. Results use a versioned 30-day local cache and report
          match/no-match/offline/rate-limit/unavailable states instead of
          silently turning missing network evidence into novelty. Cached
          results can be used offline and update catalog-novelty scoring.
          TNS live behaviour still depends on a user-provided API key and all
          provider contracts need continued monitoring as their services evolve.

[DONE]    Physical inconsistency receives persisted Gaia records
          The scoring code consumes Gaia parallax, colour and absolute
          magnitude, and is tested against them, but the real run scored
          n/a because the acquired dataset is ZTF-only. Another 15% of
          the weight is therefore unused in practice.
          => Acquire Gaia alongside ZTF for the same cones.

[KNOWN]   Composite score renormalises over available components
          With physical_inconsistency and catalog_novelty both missing,
          the real run used only 0.75 of the total weight. Scores are
          renormalised so candidates are not punished for unqueried
          evidence, but that means a score of 0.70 computed from 75% of
          the evidence is NOT comparable with 0.70 from 100% of it.
          `weight_used` is reported alongside every score for this
          reason. Cross-run comparison must check it.

[PARTIAL] Period-luminosity class centres are approximate
          PERIOD_LUMINOSITY_CLASSES holds rough class centres for Delta
          Scuti, RR Lyrae and Cepheids. It is a screen for gross
          inconsistency, not a classifier, and has no extinction
          correction — reddening will shift real objects off the locus
          and can manufacture apparent inconsistency in the plane.
          Gaia-derived A_G/E(BP-RP) values are now consumed when available;
          the uncorrected screen remains the explicit fallback.

[DONE]    Labels feed an auditable calibrated supervised ranker
          interesting/needs_follow_up versus artifact/known_object labels are
          fitted by a grouped, held-out calibrated logistic ranker. Training
          requires 50 usable labels, 10 per class, and two independent object
          groups per class; it persists the model, label snapshot, split,
          metrics, confidence intervals, schema hashes, and checksum. Applying
          a trained model is an explicit action that adds supervised
          probabilities and re-ranks candidates. A new installation remains
          intentionally untrainable until it satisfies that data gate.

[PARTIAL] Artifact indicator weights are hand-set  <-- UPDATED 2026-08-18
          The weights in artifact.assess are judgement calls combined as
          independent probabilities (now centralised in artifact.WEIGHTS,
          previously inline literals -- same values, just a single place to
          read and change them).
          INVESTIGATED: no external dataset fits. SNAD's ZTF DR3 "Dataset of
          artefacts" (arXiv:2504.08053, 1,127 objects / 1,213 labels), the
          candidate identified for this in an earlier pass, turns out to
          publish 28x28 / 63x63 FITS IMAGE cutouts with no ZTF object IDs
          and no light-curve data at all. artifact.assess operates entirely
          on one curve's own light-curve statistics (period, chi-square,
          amplitude/error ratio, kurtosis, change-point score), none of
          which an image cutout can supply. SNAD's broader anomaly tooling
          (zwad) does publish real light-curve FEATURES with real object
          IDs, but no bundled artifact/real ground-truth labels to
          calibrate against. ASTRA's own human-in-the-loop labels (1 total,
          "interesting", zero "artifact") are nowhere near usable either.
          BUILT INSTEAD: artifact.calibrate_from_injection(), a synthetic
          injection-recovery study for the six indicators that threshold a
          statistic of one curve's own features (sampling_period,
          low_significance, consistent_with_constant, sparse_sampling,
          step_change, extreme_outliers -- collected in
          FEATURE_INDICATOR_NAMES). Real, unremarkable synthetic variables
          get label 0; each "artifact" curve carries exactly one
          deliberately injected defect, so the ground truth is true by
          construction, the same idea evaluate.py already uses for the
          anomaly-detection ensemble. Every synthetic curve goes through
          the real features.extract()/artifact.assess() code paths -- the
          study does not reimplement assess()'s threshold logic, so it
          cannot silently drift from what assess() actually checks.
          The remaining four WEIGHTS entries (single_instrument,
          blended_photometry, agreement_not_independent,
          period_disagreement) are structural/categorical -- cross-survey
          resolution and period agreement, not a threshold on one curve's
          own statistics -- and a single synthetic curve cannot represent
          them; they are not calibrated by this study and stay hand-set.
          MEASURED (5 seeds, 150 real + 150 artifact per seed, held out
          30%): every one of the six fires reliably on its own injected
          defect (100% across a 60-sample verification sweep per kind) and
          essentially never on a clean synthetic real curve (0/80 for five
          of six; sampling_period false-fired 2/80, ~2.5%, consistent with
          this codebase's own documented period-aliasing behaviour).
          Calibrated weights came back 0.95-1.0 for all six -- versus the
          hand-set 0.20-0.35 -- with held-out AUC improving 0.9807 ->
          0.9939.
          NOT ADOPTED, by explicit choice, and correctly so: a synthetic
          "real" class this clean and well-separated will always make an
          indicator look more reliable than it is on messy real data (a
          genuinely eruptive variable with real large outliers, a real
          eclipsing binary with a real step, a real short-baseline
          detection). A weight of exactly 1.0 is also a real behavioural
          change, not just a bigger number: it pins the pre-clearing
          likelihood at 100% the instant that indicator fires alone,
          removing any influence from what else did or did not fire. The
          held-out AUC comparison is weak evidence either way -- both
          numbers are already near the ceiling because the synthetic
          populations are easy to separate. WEIGHTS keeps its hand-set
          values; this is a validated MECHANISM (the code runs, produces
          directionally sensible, reproducible results) rather than a
          calibration ready to deploy.
          => Worth re-running once either a harder/adversarial synthetic

          ensemble let the skew leak through.

          detector's RANK (scipy.stats.rankdata, average-tie method,

          detector's score distribution by construction, so a plateaued or
          skewed detector can no longer distort the consensus just by
          having an unusual shape -- deliberately the safer of the three

          performance / drop the weak detector / rank-aggregate), because it
          does not bake in weights measured on one dataset with one

[KNOWN]   Released builds cannot run the Phase 5 deep models
          By design. The shipped engine excludes torch/torchvision/cupy, so
          `deep.train` and `deep.compare(include_deep=True)` are unavailable
          in any installed copy. Everything else — acquisition, features,
          baseline anomaly detection, cross-survey matching, ranking and
          export — works normally in the installed app.
          This is safe because NO engine module imports torch at module top
          level; all six call sites are function-local and guarded, so the
          absence degrades rather than breaking startup.
          The packaged build originally reported a bare "No module named
          'torch'", which reads like a broken installation. rpc.py now raises
          an explicit message naming the trade-off and pointing at
          `uv pip install -e engine[gpu]`, with regression tests in
          tests/test_rpc.py::TestDeepModelsWithoutTorch that also assert the
          engine survives the refusal.
          => To train deep models, run from a development checkout.
